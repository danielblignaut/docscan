# General document text capture

The `Document text` card (`?mode=text`) captures an upright printed page
hands-free, using the same outline, quality, stability and perspective
correction as proof of address. Uploaded photos use the same reader. The camera
is released before OCR; leaving while OCR runs suppresses the late result and
completion events.

## API

`Scanner.text_page(rgba, width, height)` (wasm) and
`Scanner::text_page_native` (Rust) return:

- `text`: lines joined with newlines;
- `words`: text, `x`, `y`, `w`, `h`, and zero-based `line`;
- `lines`: text and bounding rectangles;
- `page_size`: dimensions of the enhanced, deskewed coordinate space;
- `timings_ms`: enhancement and OCR times.

Input must be an upright, flattened RGBA page. The caller can find and flatten
it with `page` and `flatten`. The reader retains the existing 1754-pixel page
processing budget and the strip detector (tile fallback if that optional model
is absent), then recognises complete lines. This avoids shrinking all of a
page's small print into the ID reader's fixed detection input. The existing
`text` API is retained, with its original output and cost.

`docscan:text` fires once after a live capture, carrying `result`, `imageUrl`
and `blob`, followed by `docscan:complete`. Photo uploads produce results but
do not fire live-capture events. The result screen offers plain-text copying
and copying the complete JSON with word positions.

Coordinates are **not** coordinates on the original photo or the smaller JPEG
preview. Reading order is row-based with gaps split into separate lines; this
is not semantic table recognition or paragraph ordering across columns. The
underlying OCR recognises the Latin alphabet. Blank/unreadable pages return
empty text, not a claim of successful extraction.

## Reproducible DEV measurement

The fixture generator and scorer were committed before the new reader. All
12 pages are synthetic: prose and invoice layouts, three font sizes, with and
without uneven illumination. No personal documents, TEST data, or trained
weights were used to choose the implementation. The two paths run through the
same native binary and models. This is a development smoke corpus, **not a
representative real-world benchmark**.

```
PATH="$HOME/.cargo/bin:$PATH" cargo build --release --manifest-path docscan/Cargo.toml --example text
/tmp/docscan-bench/venv/bin/python eval/text_eval.py --binary docscan/target/release/examples/text
```

Raw result: `eval/results/general-text-dev-v1.json` (fixture and binary hashes,
per-page errors and times). Normalised case-insensitive alphanumeric scoring:

| Metric | Existing text reader | New page reader |
| --- | ---: | ---: |
| Character error rate | 5.12% | 0.29% |
| Word recall | 92.67% | 99.11% |
| Extra words | 28 | 3 |
| Mean native latency | 1.23 s | 2.58 s |

The accuracy gain costs about twice the CPU time in this run. These timing
passes are sequential on a shared machine, not an interleaved latency study;
do not treat their ratio as a statistically established speed result. No
existing scanner is switched to this slower path.

## Research context and next measurements

The upstream [ocrs engine](https://github.com/robertknight/ocrs) separates
word detection, line grouping and recognition. Its own documentation describes
it as a preview with more errors than commercial engines. The current
[RT-DocLayout paper](https://arxiv.org/abs/2606.23344) motivates measuring
geometric rectification and reading order separately from transcription.
Neither source establishes quality for this implementation. A larger held-out
corpus of consented real pages, multiple columns, tables, thermal receipts,
rotation, curved pages and phone measurements is still required. No new model
licence or unmeasured VLM dependency is introduced here.

## Browser checks

After rebuilding wasm, refreshing `scripts/fetch-models.sh`, and building the
demo, run `cd demo && node e2e/text.mjs`. The test covers a small-print upload,
versioned model caching, hands-free capture, one completion event, released
camera tracks, and leaving while OCR is pending. Synthetic fixtures are
regenerated by the DEV command above. Browser checks do not replace testing on
physical phones.

Model download URLs now contain a hash of the served model bytes, computed at
build time. Updated tagger/OCR/face weights therefore do not remain hidden
behind an older Cache API entry on a returning visitor's device. This is cache
versioning, not a security or model-authenticity guarantee.
