# PP-OCRv6 native feasibility experiment

The official PP-OCRv6 tiny ONNX pair is a practical candidate for an optional
browser OCR engine: both graphs execute in the project's RTen 0.26, and the
native ONNX Runtime pipeline reads all 12 frozen synthetic DEV pages without
normalized character errors. This experiment does not integrate an engine or
establish real-document or browser performance.

## Availability and provenance

PaddleOCR's [3.7.0 release](https://github.com/PaddlePaddle/PaddleOCR/releases/tag/v3.7.0)
announced PP-OCRv6 on 11 June 2026. The official
[technical documentation](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv6/PP-OCRv6.en.md)
and [model collection](https://huggingface.co/collections/PaddlePaddle/pp-ocrv6)
identify tiny/small/medium variants. This experiment downloaded actual official
ONNX weights, not a third-party conversion.

| Artifact | Pinned HF revision | ONNX bytes |
| --- | --- | ---: |
| [tiny detector](https://huggingface.co/PaddlePaddle/PP-OCRv6_tiny_det_onnx) | `2ba1506c0380b8f0b03dd142459aac66d4421f6c` | 1,780,590 |
| [tiny recognizer](https://huggingface.co/PaddlePaddle/PP-OCRv6_tiny_rec_onnx) | `2612ab37152ae0a677521bae4e1e3d4fb4cf7c30` | 4,462,639 |
| [small detector](https://huggingface.co/PaddlePaddle/PP-OCRv6_small_det_onnx) | `28fe5895c24fd108c19eb3e8479f4ab385fbfc62` | 9,880,512 |
| [small recognizer](https://huggingface.co/PaddlePaddle/PP-OCRv6_small_rec_onnx) | `b8f84f0b80c529de40b4fbb3544b84fa7233a513` | 21,159,378 |

All four official model cards declare Apache-2.0. `models.json` pins revisions,
URLs, exact sizes and SHA-256 for weights, YAML configurations and model cards.
Weights stay outside git, under `/tmp/docscan-ppocr-v6`. The tiny pair totals
6,243,229 uncompressed bytes; the small pair totals 31,039,890 bytes.

Preprocessing, DB geometry and CTC conventions follow the model YAML and
PaddleX at [`ffb64904d23708863ff5b8da312a5cbd52a7f462`](https://github.com/PaddlePaddle/PaddleX/tree/ffb64904d23708863ff5b8da312a5cbd52a7f462/paddlex/inference/models):
`text_detection/predictor.py`, `text_detection/processors.py` and
`text_recognition/processors.py`. Adapted code retains Apache-2.0 attribution
in `evaluate.py`; this is a reduced standalone experiment, not the complete
PaddleX pipeline.

## Fixed DEV comparison

Inputs are the 12 pages already generated by `eval/text_eval.py` in
`/tmp/docscan-text-dev`, with no personal documents. The runner regenerates the
truth in a temporary directory and requires every image hash to equal both the
frozen image and the original baseline report. It reuses the original text
normalizer and edit-distance scorer. Metrics ignore case and punctuation.

| Engine/settings | Normalized CER | Word recall | Extra words |
| --- | ---: | ---: | ---: |
| Existing legacy OCR | 5.1198% | 92.6667% | 28 |
| Existing page OCR | 0.2905% | 99.1111% | 3 |
| PP-OCRv6 tiny, max side 960 | 0% | 100% | 0 |
| PP-OCRv6 small, max side 960 | 0% | 100% | 0 |
| PP-OCRv6 tiny, max side 1754 | 0% | 100% | 0 |
| PP-OCRv6 small, max side 1754 | 0.0363% | 99.5556% | 1 |

Both settings were specified before measuring: max side 960 is the upstream
v6 default; 1754 retains these pages' source resolution to expose resolution
sensitivity. All outcomes, including the small-model error, are retained in
`evidence/results.json`. No tuning loop, training or paid service was used.

Native ONNX Runtime used two intra-op threads and one inter-op thread. Timing
is recorded but is one uncalibrated pass on a shared machine, unpaired with
the old baseline. **No speedup claim follows.** Twelve simple English pages
cannot validate multilingual accuracy, difficult layouts, handwriting,
real-document robustness, or frontier superiority.

## RTen compatibility

`evidence/graphs.json` records actual graph operators and shapes. Detectors
(opset 14) accept dynamic `[N,3,H,W]`; recognizers (opset 11) accept
`[N,3,48,W]`. Tiny recognition emits 6906 classes and small recognition 18710.
The dictionaries are the official YAML list, preceded by CTC blank and followed
by space. All four graphs load and execute in RTen 0.26 without conversion.

`evidence/parity.json` compares real inputs from the final DEV page against
ONNX Runtime. The full-page input is `[1,3,1760,1248]`; recognizer inputs have
widths 670 and 668. Tiny detection and both recognizers satisfy
`rtol=1e-3, atol=1e-4`. Tiny detection has zero different threshold-mask pixels;
both recognizers have identical CTC argmax sequences. Small detection fails
the numerical tolerance (maximum absolute difference 0.000624), changing two
of 2,196,480 threshold-mask pixels. That discrepancy is reported, not hidden.

This establishes native operator/shape feasibility, not WebAssembly parity,
phone memory limits or a browser speed result. A shipped engine still needs
Rust preprocessing/postprocessing, correct line-coordinate mapping, resource
bounds, lazy model loading, broader DEV evaluation and browser verification.

## Reproduce

```sh
uv venv --python 3.12 /tmp/docscan-ppocr-v6/venv
uv pip install --python /tmp/docscan-ppocr-v6/venv/bin/python -r experiments/ppocr_v6/requirements.txt
/tmp/docscan-ppocr-v6/venv/bin/python experiments/ppocr_v6/fetch_models.py
/tmp/docscan-ppocr-v6/venv/bin/python experiments/ppocr_v6/evaluate.py \
  --scorer eval/text_eval.py --out /tmp/docscan-ppocr-v6/results.json --jobs 2
```

The general-text corpus and original `results.json` must already exist; this
experiment never overwrites them. To run the RTen probe, first build docscan's
native release dependencies, then:

```sh
python3 experiments/ppocr_v6/build_probe.py
/tmp/docscan-ppocr-v6/venv/bin/python experiments/ppocr_v6/check_parity.py \
  --probe /tmp/docscan-ppocr-v6/rten-probe --out /tmp/docscan-ppocr-v6/parity.json
```

No model binaries, generated pages or raw input tensors are committed.
